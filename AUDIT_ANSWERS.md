# Symbol Web: ответы и демонстрации для аудитора

Документ описывает фактическую реализацию надстройки. Он покрывает все пункты выданного аудита и дополнительные вопросы о границах, безопасности и тестировании. Неизвестные заранее вопросы невозможно перечислить исчерпывающе; ответы ниже опираются на код и воспроизводимые проверки.

**Проверяемая команда:** `go run ./cmd/web`. Адрес: <http://127.0.0.1:8080>. Исходный `cmd/server/main.go` сохранён по условию владельца и не включает готовую надстройку. Это различие нужно сообщить до начала проверки.

## Пять основных вопросов из задания

### 1. Что происходит при запросе `/api/suggest`?

Браузер ждёт 300 ms после последнего изменения и при длине от трёх символов делает POST с JSON. `Web.ServeHTTP` проверяет маршрут и метод. `Web.api` ограничивает тело, проверяет Content-Type, JSON и текст, затем передаёт контекст запроса в `Service.Suggest`. Сервис сначала смотрит в кэш. В mock-режиме он строит готовые варианты. В live-режиме `complete` делает HTTP POST к совместимому LLM-сервису. Ответ проверяется, успешные подсказки попадают в кэш на 5 минут, обработчик возвращает JSON. Браузер создаёт кнопки через DOM API; нажатие вставляет выбранный текст.

Код: `internal/handlers/web.go`, `internal/ai/service.go`, `static/js/studio.js`.

### 2. Как выбирается mock-режим и зачем он нужен?

`NewAIClient` читает переменные окружения. `Service.Mock` проверяет, пуст ли `LLM_BASE_URL` после удаления внешних пробелов. Если пуст — сетевого вызова нет. Для одинакового текста получаются одинаковые ответы; ключ и установленная модель не нужны. Это обычный режим, обозначенный в интерфейсе и заголовке `X-AI-Mode`. При заданном, но неработающем backend происходит ошибка live-запроса, а не незаметное переключение на mock.

```sh
LLM_BASE_URL= LLM_MODEL= go run ./cmd/web
curl -i http://127.0.0.1:8080/api/suggest \
  -H 'Content-Type: application/json' -d '{"text":"Hello"}'
```

### 3. Почему `/api/recommend-banner` не требует LLM?

Здесь задача решается простой функцией от длины и регистра. После удаления внешних пробелов правила применяются по порядку:

| Условие | Стиль | Пример |
| --- | --- | --- |
| Есть буквы и все заглавные, либо длина ≤ 6 | `shadow` | `WELCOME`, `Hi` |
| Иначе длина > 12 | `standard` | `Hello, everyone` |
| Иначе | `thinkertoy` | `HelloHi`, `Hello world!` |

Правила стабильны, быстры и объяснимы; внешний сервис не даёт здесь необходимого преимущества. Вызов возвращает две альтернативы с причинами. Длинный uppercase тоже выбирает `shadow`: первое правило имеет приоритет. Строка из цифр не считается uppercase. Дополнительное правило для знаков не введено: используется детерминированная схема из примера ТЗ.

Код: `internal/ai/rules.go`, тест `TestRules`. Даже при сломанном `Assistant` рекомендация работает: тест `TestAIFailureIsolation`.

### 4. Что произойдёт, если LLM медленная или выключена?

Исходный `http.Client` имеет `Timeout: 10 * time.Second`. `complete` дополнительно создаёт контекст со сроком 10 секунд, связанный с входящим запросом. Ошибка соединения, таймаут, upstream 429/5xx превращаются в `ErrUnavailable`; `Web.aiError` отвечает `503` с понятным JSON. Сервер не вызывает `panic` или `os.Exit`. Генератор, страница и правила продолжают работать. Тест таймаута действительно ждёт около десяти секунд, а не просто проверяет число в конфигурации.

```sh
go test ./internal/ai -run TestTimeoutAndCancellation -v -timeout 30s
go test ./internal/handlers -run TestAIFailureIsolation -v
```

### 5. Откуда берутся адрес и модель?

Из `LLM_BASE_URL` и `LLM_MODEL`, считанных существующим `NewAIClient` при запуске. Это позволяет выбирать локальный или удалённый backend без пересборки. Полный путь метода формируется из базового URL. В коде нет фиксированного имени модели или адреса провайдера. После изменения окружения сервер нужно перезапустить. Необязательный `LLM_API_KEY` считывается надстройкой и передаётся как Bearer-заголовок.

## Структура и сохранение работы команды

### Почему добавлена отдельная команда `cmd/web`?

Владелец запретил менять работу asamat/abaitas и их архитектуру. Поэтому исходный сервер и его пустые AI-обработчики не переписаны. Новая команда собирает расширения тех же слоёв `handlers`, `ai`, `ascii`. Это явная точка подключения, указанная первой в README. Запуск старой команды не проверяет готовую версию.

### Исходный код действительно не изменился?

Да: 22 исходных файла совпадают по Git blob-хэшам с базой `76b2ff9`. Исключение — изначально пустой README, который заполнен по прямому запросу. Баннеры, `go.mod`, `.env.example`, первоначальные Go/HTML/CSS/JS-файлы и история коммитов сохранены.

```sh
python3 scripts/verify_preserved.py
git log --format='%h %an <%ae> %s'
```

### Почему не используется старый `Generate`?

Он собирает результат в общей переменной `artResult`, что небезопасно при параллельных запросах. Старый `Banner` при ошибке открытия вызывает `os.Exit(1)`. Надстройка добавляет `ascii.Render`, который возвращает ошибки и использует локальный буфер, сохраняя формулу `initPositions` из исходного пакета. Это расширение без изменения оригинала.

### Есть ли требуемые каталоги и файлы?

Да: `cmd`, `internal/handlers`, `internal/ai`, `internal/ascii`, `templates`, `static`, три баннера в корне, `.env.example`, `go.mod`, README. Новые реализации имеют дополнительные имена, чтобы не затронуть существующие файлы. Тесты находятся рядом с проверяемыми пакетами.

### Нужен ли `go.sum`? Есть ли сторонние зависимости?

В Go-коде используются только стандартные пакеты, поэтому `go.sum` не требуется. В frontend нет npm-пакетов или внешних шрифтов. Node.js нужен только для необязательной проверки синтаксиса JS, Python — для проверки сохранности файлов.

## Генератор и HTTP

### Как из одного символа получается рисунок?

В баннере каждая буква занимает восемь строк после пустого разделителя. `initPositions` вычисляет первую строку по ASCII-коду. Генератор идёт по восьми строкам высоты и для каждой последовательно добавляет нужную часть всех букв. `strings.Builder` принадлежит одному запросу.

### Совпадают ли два контрольных примера?

Да. В `internal/ascii/testdata` сохранены примеры из выданного аудита. `TestAuditExamples` сравнивает `{123}\n<Hello> (World)!` в Standard и `123 T/fs#R` в Thinkertoy. Для сравнения визуального рисунка убираются только конечные пробелы строк и внешние пустые строки, поскольку в тексте аудита они не сохранены. Внутренние пробелы и взаимное расположение символов сравниваются. Отдельные тесты проверяют точные переводы строк.

### Какие символы поддерживаются?

ASCII 32–126 и перенос строки. CRLF нормализуется в LF. Запись из двух символов `\n` тоже превращается в перенос. Кириллица, emoji, табуляция, NUL, DEL и одиночный CR отклоняются с `400`, поскольку соответствующих рисунков в баннерах нет.

### Что с пустым вводом, пробелами и длинным текстом?

Пустая строка и ввод длиннее 1000 байт отклоняются. У допустимого ASCII один символ занимает один байт. Пробелы и пустые строки генератор сохраняет, поэтому непустая надпись только из пробелов допустима. AI-методы дополнительно отклоняют ввод, состоящий только из пробелов/переносов; suggest требует длину обрезанного по краям текста от трёх.

### Можно ли передать путь вместо баннера?

Нет. `BannerName` принимает только `standard`, `shadow`, `thinkertoy` и их варианты с `.txt`. Вход `../../etc/passwd` получает `400` до открытия файла. Статика также разрешена только по двум точным маршрутам: каталог нельзя просмотреть через браузер.

### Что происходит при повреждённом баннере?

Сервис проверяет размер файла, 855 строк таблицы, разделители, максимальную ширину и допустимые символы. Отсутствие файла — `404`, повреждение или ошибка чтения — `500`. Ошибка возвращается через HTTP и не завершает сервер.

### Почему GET и POST разделены?

GET загружает страницу или статический ресурс; POST передаёт форму или данные API. Неправильный метод получает `405` и заголовок `Allow`. HEAD поддерживается для страницы и статики. Неизвестный маршрут не попадает в главную страницу: он получает `404`.

### Как показать 400, 404 и 405?

```sh
curl -i http://127.0.0.1:8080/symbol-art -d 'inputWord=&banners=standard'
curl -i http://127.0.0.1:8080/no-such-page
curl -i http://127.0.0.1:8080/api/suggest
```

`500` безопасно демонстрируется тестами повреждённого шаблона/ответа LLM без изменения рабочих файлов:

```sh
go test ./internal/handlers -run 'TestMissingAndBrokenResources|TestAIFailureIsolation' -v
```

### Чем отличаются 500, 503 и 415?

`500` означает внутренний сбой, неправильную конфигурацию или неожиданный формат upstream-ответа. `503` — временную недоступность AI/лимит одновременных вызовов. `415` — неподдерживаемый Content-Type: форма ждёт URL-encoded, API — JSON. На API-маршрутах все эти ответы остаются JSON.

### Почему шаблон сначала выполняется в буфер?

Если писать прямо в ответ, ошибка после первой записи уже не позволит заменить статус `200` на `500`. Промежуточный буфер даёт возможность проверить успешное выполнение целиком. `html/template` автоматически экранирует пользовательские значения. При поломке шаблона ошибки остаётся текстовый резервный ответ.

### Ограничены ли большие запросы?

Да. `http.MaxBytesReader` ограничивает тело 16 KiB, текст — 1000 символами. У HTTP-сервера ограничены заголовки и время чтения/записи. Баннер и ответ LLM тоже читаются через ограниченный reader. Это ограничивает работу одного запроса; защита публичного хостинга от DDoS требует отдельной инфраструктуры.

## LLM и кэш

### Это настоящий LLM-запрос или имитация?

Оба режима реализованы явно. При пустом адресе — имитация с готовыми вариантами. При непустом — реальный `client.Do` к `/v1/chat/completions` или совместимому пути. В live передаются модель, сообщения и `stream:false`. Внешняя модель не запускалась в рамках локальной проверки: протокол проверен локальным HTTP-backend с контролируемыми ответами. Тест сервиса и реальный вывод произвольной модели — разные проверки.

### Какой формат ответа ожидается?

OpenAI-совместимый конверт с одной записью `choices[0].message.content`. Внутри content — JSON-массив 3–5 строк для suggest либо 3–5 объектов для variations. Текст каждой идеи занимает 1–49 печатных ASCII-символов; варианты должны быть уникальными. Описание варианта — 1–29 Unicode-символов, стиль — строго один из трёх. Markdown-обёртки, обрезанные данные и неправильные типы не угадываются, а отклоняются.

### Почему проверяется результат модели?

Модель может проигнорировать формат, вернуть unsupported-символы, слишком длинный текст или несуществующий стиль. Проверка не позволяет передать такой ответ в генератор как корректную подсказку. Текст пользователя передаётся как данные в JSON, а frontend выводит ответ через `textContent`.

### Что при отключённом клиенте или отмене запроса?

Исходящий запрос наследует контекст входящего. Отмена прекращает сетевую операцию и освобождает слот. На frontend предыдущий `AbortController` отменяется при новом вводе; дополнительная проверка идентичности запроса защищает от позднего ответа. При закрытии сервера общий контекст тоже отменяется.

### Может ли LLM перенаправить запрос на другой адрес?

HTTP-редиректы запрещены. Backend задаёт оператор через окружение; пользователь формы не может изменить URL. URL с встроенными credentials, query или fragment не принимается. Ключ передаётся заголовком только выбранному backend и не печатается в журнале.

### Как устроен кэш?

Ключ — валидированный текст. Значение — копия массива подсказок и срок истечения. TTL — 5 минут, вместимость — 256. Доступ защищён `sync.Mutex`. При заполнении сначала удаляются истёкшие записи, затем одна запись, если места всё ещё нет. Это простой ограниченный кэш, не LRU. Массив копируется при сохранении/выдаче. Ошибки и variations не кэшируются.

### Есть ли защита от множества запросов к LLM?

Канал вместимостью восемь ограничивает число одновременных внешних вызовов на экземпляр сервера. Если все места заняты, возвращается `503`; не создаётся бесконечная очередь. Это ограничение параллельности, а не персональный rate limit по IP.

### Есть ли retry и fallback?

Автоматических повторов нет: они могут умножить нагрузку и платные вызовы. Пользователь может повторить действие. Отдельные функции изолированы от отказа LLM. Mock выбирается только конфигурацией, не скрывает сбой live-сервиса. Для ошибок шаблона есть резервный текстовый ответ, для недоступного localStorage — история в памяти, для clipboard — выделение текста и скачивание.

## Интерфейс и безопасность

### Как проверяется debounce?

Скрипт очищает предыдущий таймер и ставит новый на 300 ms. На двух символах вызова быть не должно; после быстрого набора `Hello` должен уйти один запрос с окончательным значением. Это можно видеть во вкладке Network браузера. В ответе появляется 3–5 кнопок. Escape скрывает подсказки и отменяет ожидание.

### Используется ли fetch без перезагрузки?

Да: генерация, подсказки, правила и идеи работают асинхронно. При отключённом JS HTML-форма отправляет обычный POST и получает полностью отрисованную страницу с результатом. Основной сценарий не зависит от JS.

### Можно ли выбрать подсказку и творческий вариант?

Подсказка заполняет поле, сохраняя выбранный стиль. Творческий вариант одновременно подставляет текст и рекомендуемый баннер. Дальше пользователь нажимает «Создать ASCII-арт». Подбор стиля показывает причину и отмечает radio-карточку.

### Как защищён интерфейс от XSS?

На сервере используется `html/template`, на клиенте — `textContent` и создание DOM-элементов. Пользовательский или AI-текст не попадает в `innerHTML`. CSP разрешает скрипты/стили только с того же origin, запрещает inline-script, object, frames и чужой form-action. Строка `<script>...</script>` остаётся текстом; это покрыто тестом `TestFormAndEscaping`.

### Как обеспечивается доступность?

У textarea есть label и описание, у переключателей — fieldset/legend, у кнопок — текст. Есть видимый клавиатурный focus, skip-link, aria-live для статусов и aria-busy для ожидания. Результат доступен с клавиатуры и прокручивается горизонтально. При `prefers-reduced-motion` отключены переходы. Это набор проверяемых мер, а не заявление о формальной сертификации WCAG.

### Как работает история и что сохраняется?

В `localStorage` сохраняется максимум восемь пар `{text,banner}`. Сам ASCII-рисунок не хранится. История не передаётся на сервер автоматически; при нажатии запись повторно генерируется. Повреждённые или недопустимые сохранённые значения фильтруются. При отказе хранилища используется память страницы. Кнопка очистки удаляет только записи приложения.

### Что если clipboard заблокирован?

Ожидание ограничено 1,5 секунды. При успехе отображается подтверждение. При отказе выделяется текст результата и предлагается Ctrl+C/⌘C либо скачивание. Скачать можно через Blob с фиксированным безопасным именем, содержащим один из трёх стилей.

### Что происходит, если изменить текст во время запроса?

Текущий запрос отменяется, старые подсказки скрываются. Генерация дополнительно сверяет текст и стиль с исходным снимком перед отображением. Уже готовый рисунок остаётся доступным для сохранения, а статус сообщает, что нужно обновить результат.

## Тесты, границы и бонусы

### Какие проверки автоматизированы?

Эталонные рисунки, все 95 печатных ASCII-символов, переносы строк, границы длины, неверные баннеры, повреждённые файлы, методы и маршруты, JSON-валидация, XSS-экранирование, ошибки шаблона, mock, правила, live-протокол, ключ, плохие ответы/статусы LLM, таймаут, отмена, кэш и параллельность. Есть два fuzz-теста. Полный запуск: `make audit`; случайный ввод: `make fuzz`.

### Были ли гонки или падения?

В выполненном `go test -race` гонок не обнаружено. Фаззинг и HTTP-нагрузка завершились успешно; точные результаты находятся в `AUDIT_REPORT.md`. Утверждение относится к проверенным сценариям надстройки, а не к исходному серверу или всем возможным условиям.

### Почему общий процент покрытия выглядит ниже покрытия новых функций?

В знаменатель входят сохранённые исходные функции и обе команды `main`, которые модульные тесты не вызывают. Искусственно менять чужой код или исключать его из отчёта ради красивой цифры не нужно. В отчёте отдельно показаны общий результат, новые функции и ручные проверки реального запуска.

### Какие бонусы реализованы?

Варианты текста с LLM/mock; пятиминутный ограниченный кэш подсказок; локальная история; копирование и `.txt`; отмена устаревших запросов; резервные сценарии для ошибок UI. Автоматический retry не заявляется. Подбор баннера по правилам относится к основной части ТЗ, не является вызовом модели.

### Что ещё нужно проверить перед публичным запуском?

Конкретную модель и её способность возвращать заданный JSON, совместимость выбранного провайдера, целевой браузер, окружение и инфраструктурные ограничения. Публичный TLS/reverse proxy и защита от внешнего потока запросов не входят в локальную поставку. Нет обещания пройти любой неизвестный аудит; есть соответствие описанным требованиям и проверяемые доказательства.

## Короткая демонстрация за пять минут

1. Запустить `LLM_BASE_URL= go run ./cmd/web`, показать отметку демо.
2. Отрисовать два примера из аудита, переключить все три стиля.
3. Набрать два символа, затем три и больше; выбрать подсказку.
4. Сравнить рекомендации для `WELCOME`, `HelloHi`, `Hello, everyone`.
5. Выбрать творческий вариант, скопировать/скачать рисунок и восстановить историю.
6. Показать `400`, `404`, `405` командами выше и `500`/`503` тестами.
7. Запустить `make audit` и проверку сохранности исходных файлов; открыть `AUDIT_REPORT.md`.
